## 2. Database hot paths: defect found and fixed (BUG-06)
`EXPLAIN ANALYZE` on PostgreSQL 16 with synthetic volume for a hosted, multi-tenant database: 400,000 shifts and 600,000 WhatsApp messages across 1,000 pharmacies (script and plans: `evidence/perf-indexes.sql`, `evidence/explain-before-after.txt`).

| Query | Where it runs | Before (plan, time) | After (plan, time) |
|---|---|---|---|
| Open shift for the counter: `Shift WHERE tenantId, branchId, closedAt IS NULL, counter` | **Every sale commit** (`lockOpenShift`, 14 call sites) | Parallel seq scan, 133k rows removed per worker, **24.5 ms** | Index scan `Shift_tenantId_branchId_closedAt_idx`, **0.061 ms** |
| WhatsApp status webhook: `WaMessage WHERE tenantId, wamid` | Every Meta status callback (sent/delivered/read, up to 3 per message) | Parallel seq scan, **38.4 ms** | Index scan `WaMessage_tenantId_wamid_idx`, **0.022 ms** |
| Messages for an invoice: `WaMessage WHERE tenantId, invoiceId` | Invoice view, resend checks | Parallel seq scan, **27.8 ms** | Index scan `WaMessage_tenantId_invoiceId_idx`, **0.018 ms** |
| Offline conflicts: `OfflineOp WHERE tenantId, status` | Sync & offline badge | Seq scan (no index) | `OfflineOp_tenantId_status_idx` |

Before the fix these costs grew linearly with the data of **all** pharmacies on the server. Migration `prisma/migrations/20261215000000_hot_path_indexes` adds the four indexes (additive only, generated by `prisma migrate diff`, which also confirmed no other drift between the schema and the migrations).

## 4. Other observations
- Live updates use one `LISTEN` connection per app server and SSE per browser; a sale's three change events arrive within ~100 ms of the commit and the screen refreshes ~700 ms later. A dropped refresh in the Next.js router (BUG-08) is now detected and retried: at most 7 refreshes per burst of changes, and only while the screen is provably behind.
- 141 `@@index` and 121 unique declarations in the schema; 21 tenant tables have no tenant-leading index. The four that sit on hot paths were fixed; the rest (`Counter`, `Invite`, `HeldCart`, `Recall`, `StockCount`, …) are small per pharmacy and were left as they are.
